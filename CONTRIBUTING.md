# Contribute to FELiCS

Thank you for your interest in contributing to FELiCS! We welcome contributions from the community to help improve the project.

## 1. Getting Started
FELiCS is under active development. Before you begin, please familiarize yourself with the project structure and guidelines:
- **Read the Documentation**: Understand the overall architecture and usage in our [Documentation](https://felics2-0-laboratory-for-flow-instabilities-and--112f91add91c56.gitlab-pages.tu-berlin.de/).
- **Developer Guidelines**: For coding standards, style guides, and documentation rules, please strictly refer to our [Developer Wiki](https://git.tu-berlin.de/laboratory-for-flow-instabilities-and-dynamics/felics2.0/-/wikis/).

## 2. Reporting Issues & Feature Requests
If you encounter a bug or have an idea for a new feature, please let us know:
- **Check Existing Issues**: Before opening a new issue, please check the [Issue Tracker](https://git.tu-berlin.de/laboratory-for-flow-instabilities-and-dynamics/felics2.0/-/issues) to see if it has already been reported.
- **Open a New Issue**: If not, create a new item in the Issue Tracker. Be sure to include a clear description, reproduction steps for bugs, or a detailed explanation for feature requests.

## 3. Development & Testing
Ensure your code is robust and does not break existing functionality:
- **Validation Cases**: Test your changes against standard validation cases, downloadable from the [FELiCS Tests Repository](https://git.tu-berlin.de/laboratory-for-flow-instabilities-and-dynamics/felics-tests).
- **Unit Tests**: All unit tests must pass locally before submission.
  - See the [Unit Tests README](tests/README.md) for instructions on how to run them.
  - Note that unit tests are also automatically run in our CI pipeline.

## 4. Submitting Changes
Ready to contribute your code?
1. **Fork & Branch**: Create a new branch for your feature or bugfix.
2. **Commit**: Write clear, concise commit messages.
3. **Merge Request**: Submit a Merge Request (MR) to the `development` branch. Link your MR to any relevant issues.
